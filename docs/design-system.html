Airtable의 편집적 절제 — 흰 캔버스, 먹색 타입, 여백, 따뜻한 시그니처 표면 — 를 일기 · 감정 기록 도메인으로 번역했다. Airtable이 코랄 · 크림 · 민트 카드로 긴 스크롤에 전압을 주듯, 우리는 그 따뜻한 팔레트를 감정에 실어 기록의 순간마다 찍는다. 색은 감정에 살고, 크롬은 조용하다.

3계층 토큰 아키텍처

값은 한 방향으로만 흐른다. 상위 계층이 바뀌면 하위 전체가 따라간다. 정본은 frontend/src/styles.css — 이 페이지에 인라인된 블록과 동일하다.

Tier 1 · Primitives

테마 불변 원시 팔레트. ink 램프 · warm 시그니처 램프 · 의미색 · warm dark 램프. 리터럴만, 테마가 바뀌어도 값 불변.

Tier 2 · Semantic

역할 토큰. 전부 var(--tier1) 참조. dark/light 재매핑의 유일한 소유지. 감정 표면 쌍(--emotion-*)도 여기.

Tier 3 · Component

별도 계층 없음. CVA variant와 컴포넌트 클래스가 Tier 2를 직접 소비 (shadcn 방식, 우리 규모에 component 토큰 계층은 과잉).

계층 계약

  • 하향 참조만 허용. 상향 참조 금지.
  • 테마 분기는 오직 Tier 2에서만. Tier 3·컴포넌트 클래스에 테마 코드 0줄.
  • fg/bg 쌍을 반드시 함께 정의 — 대비를 토큰 수준에서 보증 (Polaris · shadcn 교훈).

색상

잉크-종이 무채가 토대, 따뜻한 시그니처 팔레트는 감정의 원색, 의미색은 상태 전용. Airtable의 "color-block first, shadow second"를 따른다.

테마 — 역할 반전

다크/라이트 재매핑은 Tier 2 semantic에서만 일어난다. 라이트가 종이(밝은 캔버스)라면 다크는 그 종이의 어두운 면(따뜻한 차콜). 우측 위 토글로 전환해 확인한다.

반전 규칙
  • 낮은 잉크 칸 ↔ 높은 표면 칸의 역할을 뒤집는다 (값이 아니라 역할).
  • 근검정 CTA → 다크에선 밝은 종이 잉크 CTA로.
  • 감정 표면은 어두운 카드 위 낮은 채도 염색으로, 잉크는 밝게.
  • 컴포넌트 클래스에는 테마 코드 0줄 — 전부 var() 전환.

법적 · 윤리적 경계

Airtable의 로고 · 상표 · 전용 서체(Haas Grotesk) · 웹사이트 화면 구조(IA)는 복제하지 않는다. 가져간 것은 색 관계 · 밀도 · 위계 · 여백의 원리다. 서체는 Pretendard + 손글씨로 대체.

앱 적용 현황

  • ✅ 전역 토큰 교체 — frontend/src/styles.css 가 결 정본(앱은 토큰 정의 0, 이 페이지 인라인 블록과 동일 소스). 값은 Airtable: 잉크 중성, 따뜻한 시그니처=감정 표면, 산스 디스플레이(세리프 미사용).
  • ✅ 형태·타이포·레이아웃 전역 정리 — 버튼 전 형태 pill + weight 500, 입력 44px + 2px 잉크 포커스, font-extrabold/font-black 을 500/600 으로 감량(로고 워드마크만 예외), 화면 헤드라인 산스 디스플레이 400, hairline/elevation/반경 위계, 탭바·헤더·펀널 셸 정돈.
  • ✅ 공통 부품 확충 — ChipBadge, ChipPicker, EmotionStatBar, Skeleton, Separator, ThrowbackCard, PersonChip, Orb.
  • ✅ 칩 색상 복원 — 타임라인·상세·프로필의 카테고리·감정·관계태그를 색상 ChipBadge/TagChip 로 통일(무색 Badge 해소).
  • ✅ 회고 연결 — 홈 1년 전 오늘을 ThrowbackCard 로 연결, 표면/여백은 결 토큰 적용.
  • 📌 데이터 모델 메모 — Mongle의 감정은 고정 enum이 아니라 per-chip hex color 를 가진 동적 칩이다. 따라서 이 페이지의 6가지 감정 색은 디자인 언어의 권장 어휘·시드 팔레트(GYEOL_CHIP_PALETTE)이며, 실제 렌더는 칩 색을 그대로 쓰는 ChipBadge/TagChip 이 담당한다.
  • 📌 시각 확인 — Storybook 빌드 산출을 헤드리스로 칩·모달·몽글라인·헤드라인·회고·orb 캡처 확인. 앱 전 화면 눈 확인은 백엔드가 필요해 로컬 실행으로 요청.
